## 2. חקירת-אמת — שכבה אחר שכבה

### שכבה א' — הטריגר המקורי: הקפאת טיימר בעריכה חיה
מהיסטוריית השומר (הראיות):
```
03:58:10 — fleet-verify:UP (בפעם האחרונה)
03:58:40 — fleet-verify:ZOMBIE-1
03:59:10 — fleet-verify:ZOMBIE-2
03:59:40 — RESTART "זומבי: פעימות קפואות (hot-reload)"
```
זמן הקפאת הפעימות המדויק: **03:54** — בדיוק הרגע שבו נערך קובץ הדיבון
(mtime 03:54, מהסשן הקודם). `bun --hot` העריך את המודול מחדש, הטיימר הישן
קפא, והשומר-הקיים (`if (!G.__FV_TIMER__)`) היה **עיוור לטיימר מת**: הוא ראה
"טיימר קיים" ולא הקים חדש. HTTP עונה, פעימות קפואות — זומבי מלא.
חוק הזומבי של R91 זיהה זאת נכון (9 סיורים + חסד) — אבל ההחייאה שאחריו נשברה.

### שכבה ב' — ספירלת המוות: מרוץ-ההרגה של השומר
שורש הקוד (לפני התיקון):
```js
// ניקוי נעילות-פורט: SIGTERM, חכה, אז SIGKILL
for (const pid of pidsOnPort(d.port)) { SIGTERM }
setTimeout(() => {
  for (const pid of pidsOnPort(d.port)) { SIGKILL }   // ← בודק "מי על הפורט" בזמן ההרג!
}, 1500);
Bun.spawn([bun, --hot, index.ts])                      // ← היילוד מוקם מיד
```
**מרוץ ההרגה מוכח:** היילוד נקשר לפורט תוך ~1 ש' (מטמון חם), ה-SIGKILL
המושהה יורה ב-+1.5ש' ובודק "מי על הפורט" **ברגע ההרג** — ומוצא את היילוד
שזה עתה נקשר. כל "החייאה" רצחה את בנה של עצמה. 8 רציחות ברצף.

הוכחות ניסיות חיות:
- יומן הדיבון מראה 5 שורות "עלה" (ההקמה מסיימת bind ורק אז מדפיסה) — אך
  דגימות של 15ש' לאורך 3 דקות לא תפסו אף פורט חי אפילו פעם אחת: המוות
  תוך שניות מה-bind.
- הרצה ידנית (בלי השומר) שרדה 25ש' ומעלה — עד שהשומר הגיע למסקנת
  FAIL-3 והרג גם אותה באותו מנגנון (SIGTERM על "מי שעל הפורט").
- אין הריגות OOM חדשות ב-líbra (האחרונה 03:28, לפני הספירלה).

### שכבה ג' — חוסר אטומיות בשומר
`saveState` של השומר כתב ישירות לקובץ (בלי .tmp+rename) — הפרה של חוק
R107b. רגע-מוות באמצע כתיבה היה משאיר ליורש קובץ-מצב חצוי.

## 3. התיקונים (שני חוקים חדשים)

### חוק היילוד — בשומר (mini-services/keeper/index.ts)
```
רשימת-ההרג נתפסת לפני ההקמה; ה-SIGKILL המושהה פוגע רק בזקן
שסירב למות — לעולם לא ב"מי שעל הפורט עכשיו".
```
+ כתיבת-מצב אטומית (.tmp ואז rename) — חוק R107b נאכף גם בשומר.

הגנה זו חלה על **כל הצי** — כל דיבון שיידרש החייאה בעתיד מוגן עכשיו
ממרוץ-ההרגה (הבאג לא היה ספציפי ל-fleet-verify; הוא פשוט התגלה שם).

### חוק פעימת-החיים — בדיבון (mini-services/fleet-verify/index.ts)
```
טיימר נמדד לפי פעימותיו, לא לפי קיומו. קפוא מעל 3 מחזורים — מוחלף.
השרת-החי (שעונה ל-HTTP) הוא המשקה: כל בקשת /health בודקת את השעון
ומחייה אם צריך. מצב הזומבי עצמו (HTTP חי, טיימר מת) הופך לטריגר ההחייאה.
```
השומר שואל /health כל 30ש' — כלומר טיימר קפוא מתגלה ומוחלף תוך 30ש'
לכל היותר, הרבה לפני שחוק הזומבי של R91 (9 סיורים) נדלק מלכתחילה.
שכבת הגנה כפולה: הדיבון מחייה את עצמו פנימית, והשומר כגיבוי חיצוני.
