## 2. שלושת פגמי-השורש (מוכחים בראיות)

### באג א׳ — הזמנת המלאי תמחרה מהצד הלא-נכון של הספר (קוד-מת מלא)
`stock-sbd` קונה SBD על-ידי מכירת STEEM — ביצוע taker מתבצע מול **הבידים**.
הקוד הישן חישב את כמות ה-STEEM ממחיר-**השאלה** (הצד השני):
```

min_to_receive = 0.106 SBD               // = דרישת מחיר 0.10528 SBD/STEEM

→ "Cancelling order because it was not filled" — בכל ניסיון, בכל שוק עם ספרד
```

`stock order: Assert Exception:filled: Cancelling order because it was not filled`.

### באג ב׳ — סדר-ההחלטות הרעיב את כל השאר (דימום)
ב-`decide()` הטריגר של stock-sbd יושב **לפני** טריגר הנזיל ולפני רגל HIVE.
פער החימוש (0.044/0.15) + דלק נזיל מכסה → הזמנת המלאי יורה **בכל פעימה אחרי
צינון** → נכשלת (באג א׳) → צינון 30 דק' + תקציב נשרף → חוזר חלילה.
התוצאה הנמדדת: **הסולם לא נפרש מחדש** (476 נזילים מאז ביטולי 03:46)
ו**רגל HIVE לא קיבלה תור אף פעם** — ההחלטה לעולם לא הגיעה אליה.

### באג ג׳ — גל-השקר: ההון-העומד התחזה לדלתא (שלמות חשבונאית)
ב-04:15:56 ירה ARENA-STREAM כי "נזיל 477 ≥ 200" — חתימת פאוורדאון.
האמת שנחשפה בספר הזירה (seq#38):

כל ההון היה **נעול בפקודות סולם**. כשהפקודות בוטלו וההון שב לנזיל —
הדלתא התפרשה כדלק-חדש ו-20% ממנו (95.327) הועטפו ל-WSTEEM וזו�ווגו
לבריכה. נזק כפול: הון-סולם הוסט לעומק-זירה + **תביעה כפולה על אותו STEEM**
(הסולם מוכר אותו כדלק; הזירה גובה אותו כגיבוי 1:1 ל-WSTEEM).

## 3. התיקונים — ארבעה חוקים חדשים

| חוק | מקום | תוכן |
|---|---|---|
| **חוק הביד-הבר-ביצוע** | api/money stock-sbd | הליכת-ספר אמיתית מול הבידים (כמה STEEM נדרש לפער), פרימיית-עלות בכיוון הנכון `parity/bid − 1` (כמה STEEM מעל ההוגן עולה SBD), תקרת 200bps נאכפת בכנות; עומק לא מכסה → סירוב `BOOK-TOO-THIN` |
| **חוק הבדיקה-המוקדמת** | הדיבון decide() | הירי נבדק מול הביד מהמדידה עצמה לפני שריפת תקציב+צינון; מעל התקרה — ההחלטה נופלת בכנות הלאה (פריסה · HIVE) במקום לולאת-סירוב |
| **חוק חתימת-ההון-הכולל** | הדיבון, טריגר הגל | גל = עלייה בהון-הכולל (נזיל+פרוס) מעל המדידה הקודמת — `lastTotalSteem` נזרע בכל פעימה אמינה; ביטול/פריסה לא משנים את הכולל ולעולם לא מדליקים. אפס מדידה לא אמינה לא מאפסת את הזיכרון |
| **חוק הגיבוי** | api/money + liquidityStream | דלק-הפריסה מנכה את תביעת הזירה (כל מאזני ה-WSTEEM + רזרבות בבריכות) — הסולם לא מוכר את הגיבוי של הזירה לעולם, גם להפקדות-חוץ עתידיות; ובהזרמה עצמה שומר-גיבוי: היצע העטיפה הכולל ≤ ההון החי על השרשרת |

+ **חוק הטיימר-היחיד** הוחל על דיבון הכסף (שיעור R109 שנשאר לא-מיושם כאן):
זומבי-טיימר נתפס חי ב-05:16:54 — הסגור הישן של decide() ירה stock-sbd
עם טקסט הסיבה הקודם בזמן שהקוד החדש כבר רץ. מנגנון globalThis מנקה
את הטיימר הקודם בכל טעינה. דיבון הוקם מחדש נקי (v1.8.0) — פעימה אחת מדויקת.

## 4. ההבלגה — היפוך העטיפה הכוזבת בשרשרת-הספר

נבנה **רייל היפוך-עטיפה** (`treasury-unwrap`): מזהה אירוע WRAP מקורי לפי
seq — אין המצאת סכומים; מחלץ קודם את מניות-ה-LP של האוצר (העומק חוזר);
מקטין את יתרת האוצר עד הגבול הקיים בכנות; מסרב לעטיפות-הטבעה (WSBD/WHBD —
דורשות שריפת USDS קודם); הכל מתועד. בוצע חי:
```
POST /api/exchange { action:"treasury-unwrap", seq:38 }
→ seq#40 LP_REMOVE   (0.112 WSTEEM + 0.007204 USDS חזרו מהבריכה)
→ seq#41 TREASURY_UNWRAP { amountRequested: 95.327, amountReturned: 95.326999999, shortfall: 1e-9 }
```
אומת בספרים: אוצר WSTEEM = 0 · בריכת WSTEEM/USDS ריקה בכנות · שאר הנכסים
(WBLURT 78.55 · WHIVE · SAOS 126,206 · WSOL) לא נפגעו. קו-הבסיס שנקבע
באירוע המקורי (measuredBalance 476.637) נשאר — גלים עתידיים יזרמו רק מהון חדש.
